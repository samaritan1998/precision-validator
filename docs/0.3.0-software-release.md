# Version 0.3.0 software verification

Status: verification in progress; no final release claim until the frozen
artifact checks below complete. The currently published rc3 artifact and its
historical evidence remain available unchanged.

The software verdict concerns the validator's correct operation. Numerical
model acceptance remains a separate report result. Known generated BF16 MoE
failures are registered as expected diagnostic outcomes before this new
artifact's tests, and must still be reported as `numerical_failure`. No model
numerical threshold is relaxed for software publication.

The runtime differs from rc3 only in `precision_validator.__version__`.
Nevertheless, the final wheel gets its own fresh full CPU verification and
B200/H800/A800 matrix and integration runs. Existing rc3 executions do not
count as executions of this new wheel.

Required evidence:

- Full installed-wheel CPU tests with zero skips and an exported training example.
- Thirty complete native Slime matrix comparisons, with exact frozen outcomes
  and independent raw-vector metric audits on every case.
- Native Ray training, FP32/BF16 storage trajectory, CPU optimizer offload and
  resume, and masked HF Llama/Gemma adapters on all three device families.
- Positive native FP32 expert-gradient accumulation controls on each device.
- Capture-disabled/repeated/enabled invariance on the B200 native fixtures.
- Public installation CI, source/asset hashes, and downloaded-release verification.

The previously recorded production Qwen 256K comparison and combined BF16
TP/PP/EP findings remain unresolved model-side results. They are not model
passes, and this release will not label them as such. This library does not
claim arbitrary model support, all topology combinations, or long-run training
convergence. See [scope and historical evidence](validation.md).
